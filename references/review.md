# Semantic equivalence review

Use an independent semantic review only when it can materially change
acceptance. This is not a mandatory step for every Holytail-gated coding task.

|---|---:|---:|---|

## Review questions

- Did the problem or accepted meaning change?
- Were protected distinctions and negative requirements preserved?
- Was meaningful deferred work silently omitted?
- Did worker, reviewer, lead, memory, or file authority widen?
- Are raw references reachable and unknowns still explicit?
- Are persisted formats, migration, paths, permissions, content authority, and
  unattended execution consistent with the contract?

## Required rework or decision

Name the failed invariant, exact evidence gap, affected source, and expected
observable correction. Approval is reviewer evidence, not final acceptance.
