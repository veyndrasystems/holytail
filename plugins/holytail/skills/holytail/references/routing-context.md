# Holytail routing context

`hook_observed` means this hook ran; it proves neither activation nor compliance.
A minimizer runs only where configured; installation does not establish
activation. Holytail never mutates third-party plugin state. Hook order is not authority.

- Leave open exploration open; implementation economy cannot settle meaning.
- Use `INLINE` for clear low-risk work with proportionate response evidence.
  Already-authorized reversible operations are not formal merely because they
  have an external effect. `FULL` quality alone does not select a route or
  require files, delegation, or a reviewer.
- Use `FORMAL` for persisted/public contracts, authority/trust boundaries,
  destructive or irreversible effects, material lifecycle/evidence/identity distinctions,
  lost raw-evidence traceability, or unresolved protected meaning after
  exploration. Resolve blocking meaning through its authorized owner.
  A configured Soulmate workflow overrides this heuristic.
- The lead selects the existing route first. Every `FORMAL` task receives
  `FULL` automatically. For `INLINE`, select `FULL` when consequence or
  uncertainty is material and `ECO` otherwise. Do not ask the user solely for
  mode selection; meaning, scope, permissions, publication, and irreversible
  effects remain owner-controlled.
- Before spawning a formal child, require exactly one canonical packet line:
  `Quality mode: FULL.` Missing, duplicate, conflicting, parent-banner-only,
  minimizer-only, and reasoning-effort-only assignments fail before spawn.
  The child-side fail-closed check remains. This guidance and package
  validation do not claim native host interception.
- For formal work, read the skill, freeze an immutable contract, and use a
  bounded worker; add fresh review when decisive. In standalone formal work the
  lead alone writes `.holytail/check.md`, bound to the accepted artifact and
  implementation snapshot. The worker writes only its uniquely scoped delivery.
  Soulmate remains authority, evidence owner, and final acceptor when configured;
  do not initialize it or create a second run.

While active, begin responses with:
`Holytail :<FULL|ECO|MODE-UNBOUND> · <INLINE|FORMAL> · evidence=agent_declared`.
`agent_declared` is assertion, not verification. Worker completion, reviewer
approval, lead acceptance, and objective truth remain distinct. Codex read-only
enforcement requires its native reviewer profile; portable text is not enforcement.

Ponytail `lite`, `full`, `ultra`, and `off` are unrelated to Holytail quality
or route: `full` is not `FULL`; `ultra` is not a Holytail signal. Only an
explicit authorized project policy may map axes. Formal execution requires
`Quality mode: FULL` or an equivalent exact assignment after applying the
standing policy; otherwise report `MODE-UNBOUND` and `blocked`. A host
`reasoningEffort` label supplies quality only when that authorized policy
explicitly maps it.
