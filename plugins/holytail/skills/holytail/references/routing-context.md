# Holytail routing context

`hook_observed` means this hook ran; it proves neither activation nor compliance.
Holytail preserves accepted meaning before and after implementation and performs
no minimization. A minimizer runs only where enabled by the configured scope;
installation does not establish activation. Honor an unminimized parent and
independently enabled implementation subagents. Holytail never mutates
third-party plugin state. Hook order is not authority.

- Leave open exploration open; implementation economy cannot settle meaning.
- Use `INLINE` for clear low-risk work: a brief meaning check and proportionate
  evidence in the ordinary response. Already-authorized reversible operations
  are not formal merely because they have an external effect. `FULL` quality
  alone does not select a route or require files, delegation, or a reviewer.
- Use `FORMAL` for changes to persisted schemas/public compatibility,
  authority/permissions/trust boundaries, destructive or irreversible effects,
  material lifecycle/evidence/identity distinctions at risk, lost raw-evidence
  traceability, or first implementation after exploration with unresolved
  protected meaning. Resolve blocking meaning through its authorized owner.
  A configured Soulmate workflow overrides this heuristic.
- For formal work, read the Holytail skill and freeze an immutable contract;
  use a bounded worker; add fresh review when decisive. In standalone formal
  work the lead alone writes `.holytail/check.md`, bound to the accepted artifact
  and implementation snapshot with invariant-level findings. The worker writes
  only its uniquely scoped delivery. Soulmate remains authority, evidence owner,
  and final acceptor when configured; do not initialize it or create a second run.

While active, begin responses with:
`Holytail :<FULL|ECO|MODE-UNBOUND> · <INLINE|FORMAL> · evidence=agent_declared`.
`agent_declared` is assertion, not verification. Worker completion, reviewer
approval, lead acceptance, and objective truth remain distinct. Codex read-only
enforcement requires its native reviewer profile; portable text is not enforcement.

Ponytail `lite`, `full`, `ultra`, and `off` are unrelated to Holytail quality
or route: `full` is not `FULL`; `ultra` is not a Holytail signal. Only an
explicit authorized project policy may map axes. Formal execution requires
`Quality mode: FULL` or an equivalent exact assignment; otherwise report
`MODE-UNBOUND` and `blocked`. A host `reasoningEffort` label supplies quality
only when that authorized policy explicitly maps it.
