## Meaning-preserving minimization

Keep generic Ponytail off as a global or direct implementation mode. During
open exploration, do not let implementation economy settle product meaning,
scope, framings, or architecture. When work moves to implementation, pass
through a lightweight Holytail gate before applying Ponytail-style economy:
preserve the meaning already clear from the user's request and accepted project
instructions, identify only the distinctions materially at risk, leave the
remaining mechanism open to experimentation, and minimize inside that space.

For clear low-risk work, perform the gate inline and continue. Do not require a
separate contract document, repeated user acceptance, Holytail subagent, or
semantic reviewer. Escalate to the formal `holytail` workflow when requested or
when a shortcut could collapse a material authority, lifecycle, evidence,
security, persistence, compatibility, or decision-ownership distinction. Ask
the user only about genuine blocking ambiguity or meaning-changing choices.
Use `semanticreviewer` only when independent review can materially change
acceptance. Worker completion, reviewer approval, lead acceptance, and
objective truth remain distinct whenever those roles are used.
